# Cursor 작업 지시 — 인트라넷·클라우드 RAG 1차 연결

PM은 기존 인트라넷을 업무·승인 창구로 유지하고 클라우드에 원본·공통 검색을 두는 설계를 승인했다. Mr. Sun이 CTO로 변경 범위와 검증을 총괄한다. 이 지시는 사무실 PC의 Cursor에 전달한다.

## 1. 운영 환경 사실 확인

현재 프로젝트에서 브랜치, HEAD, 미커밋 변경 여부, 실제 실행 방식, 실행 컨테이너의 이미지/빌드 정보를 확인한다. 개발용 기준은 d9884846099312b23232c8b84023a8ec01f85d99이며 운영 코드와 같다고 가정하지 않는다. `git status --short --branch`, `git rev-parse HEAD`, `docker compose ps` 등을 환경에 맞게 사용한다. Docker 설치 여부부터 확인한다. 비밀번호·토큰·.env 내용은 출력하거나 전달하지 않는다. 기존 변경을 reset/stash로 임의 처리하지 않는다.

## 2. 작업 기준

GitHub의 codex/knowledge-contract-v0.1 브랜치에서 아래 파일을 검토한다.
- docs/French_Maison_RAG_Architecture_v0.1.md
- prototypes/knowledge-v1/core.mjs
- prototypes/knowledge-v1/core.test.mjs
- prototypes/knowledge-v1/README.md

운영 폴더에서 checkout하거나 서버를 재시작하지 않는다. 별도 worktree/개발 체크아웃을 만들고 운영 기준과 PR 차이를 비교한다. 운영 DB에 마이그레이션·db push를 실행하지 않는다. PR의 프로토타입은 배포 가능한 서버가 아니며 인증된 ctx를 클라이언트 입력으로 받아서는 안 된다.

## 3. 이번 구현 범위

먼저 기존 AI 라우트, 업로드·첨부 버전, 승인 완료 처리, 권한 검사, 색인 호출자를 추적하고 파일/함수 지도를 만든다. 동일 기능이 운영 브랜치에 이미 있으면 중복 구현하지 않는다.

독립 개발 DB에서 다음을 구현한다.
1. Document / DocumentVersion / DocumentACL / SyncEvent(outbox) / SyncJob의 영속 모델과 additive migration. 기존 Attachment와 매핑하며 삭제·파괴적 변경은 하지 않는다.
2. 원본 파일 바이트 보존과 SHA-256 검증. 이미지 압축 미리보기는 별도 객체. StorageAdapter 인터페이스와 로컬 개발 어댑터를 먼저 구현한다. 실제 클라우드 공급자는 아직 미선정이다.
3. 승인 시 특정 version_id/hash와 이벤트를 DB 트랜잭션으로 기록. 내구성 있는 재시도·이벤트 중복 처리·문서별 순서 검증.
4. 먼저 TXT/Markdown 한 문서로 추출→임시 색인 세대→승인 재확인→활성 버전 원자적 교체를 구현한다.
5. 모든 검색과 다운로드는 서버가 확인한 사용자·조직·그룹으로 제한한다. 기존 NextAuth 쿠키를 외부 에이전트 인증으로 그대로 쓰지 않는다. 외부 접속은 아직 활성화하지 않는다.
6. 기능 플래그 기본 OFF로 기존 업무와 분리한다. 검색 반영 상태와 실패 사유를 관리자 개발 화면 또는 인증된 개발 API에서 확인한다.

공통 검색 API의 최종 외부 인증, 클라우드 가입, 운영 배포와 ERP는 이번 범위에서 제외한다. 임베딩 모델을 임의 변경하지 않는다.

## 4. 검증과 반환

프로토타입 9개 테스트를 실행하고, 실제 DB 기반으로 재시작 복구·중복·역순 이벤트·교체 실패·권한 철회·부서/조직 격리·원본 해시·미승인 제외 테스트를 추가한다. 작업에 해당하는 typecheck/build와 기존 테스트를 실행한다. 실행하지 못한 항목은 이유를 명시한다.

Mr. Sun에게 아래 형식으로 결과를 반환한다.
- 운영 코드 확인 결과: 브랜치/커밋/미커밋 유무/실행 방식 (확인·추정 구분)
- 기존 구현 지도와 재사용/변경 지점
- 작업 브랜치와 커밋 또는 draft PR URL
- migration 영향과 롤백 방법
- 테스트 명령·통과/실패·미실행 이유
- 남은 결정 사항과 장애 요인

자동 병합·운영 배포·유료 서비스 가입은 하지 않는다. 설계 변경이 필요한 경우 문제와 대안을 정리해 CTO 검토 대상으로 반환한다.
