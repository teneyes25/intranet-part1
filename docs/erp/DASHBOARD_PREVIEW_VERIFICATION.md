# ERP 경영 대시보드 — 관리용 추정 통합 (2026-11-06)

## 변경 결과

`/admin/erp-dashboard`와 관리자 전용 `/api/erp/dashboard?period=YYYY-MM`에서 업로드 원본, 비용 검토, 월별 배부를 연결한다. 관리자 메뉴와 원본 검토 화면에 이동 링크를 추가했다.

- 매출: 선택 월 판매행의 세전 순매출. VAT 0행은 승인된 1.1 분리·원 단위 사사오입, 반품 부호 보존.
- 원가: 판매일 **이전** 최근 양수 매입수량·유효 도착도 단가로 관리용 추정. 같은 날 시간 순서를 알 수 없으므로 당일 매입가는 제외한다. 가장 최근 매입일에 여러 단가가 충돌하면 추정을 보류한다.
- 손익: 세전매출 − 추정 매입원가 − 현재 입력과 일치하는 검토 배부액. 원가 한 행 또는 비용이 미확정이면 전체 손익도 null이며, 부분 합계를 전체 손익으로 표시하지 않는다.
- 상품별 원가: 상품 추정 매입원가 + 배부액, 순판매수량이 양수인 경우 단위 총원가 표시. 원거래 미연결 반품은 원가 환입을 추측하지 않는다.
- 채널별 이익: 명시적인 `채널` 또는 `판매채널` 열만 사용. 미제공은 미분류. 상품 배부액을 그 상품의 채널별 세전매출 비중으로 최대잔여 배분한 **참고 추정치**이며 채널 직접비를 확정한 것은 아니다. 음수 채널 비중·0분모는 채널 비용 배부 보류.
- 재고: 선택 자료월 재고수량과 판매가 기준 평가액을 구분. 당월 양수 유효 판매의 수량 가중평균 세후 단가, 없으면 이전 최근 유효 판매일 가중평균·일자 표시. 미래 자료·불명확한 이력은 대체 근거로 사용하지 않는다. 일부 미평가 품목이 있으면 전체 평가액은 미확정이다. 실제 재고 기준일·원천 대사는 별도 확인 필요.

모든 결과는 `publishable=false`. 승인된 관리 추정 기준을 사용하지만 확정 회계 손익, 자동 취득 완료 또는 운영 인수를 의미하지 않는다. 카드/결산 샘플이 월 전체 비용을 포함하는지도 별도 검토 사항이다.

## 정합성·권한

- 현재 유효 원본과 검토 상태를 하나의 SQLite 읽기 트랜잭션에서 조회. 계산 자체는 원본·검토·배부를 쓰지 않는다.
- 원본 또는 검토 변경으로 배부 fingerprint가 달라지면 비용과 손익을 미확정으로 표시한다. 계산 버전에는 정책·자료월·입력 fingerprint·배부 ID를 포함한다.
- 판매/매입 자료의 거래월 검사. 선택 월 복수 판매 파일은 조회 차단, 복수 매입 파일은 중복 범위 확인 전 원가 추정 보류. 불명확한 과거 판매월은 과거 가격 대체 보류.
- 예전 캐시에 매입일·채널이 없으면 보존 원본으로 재검증·재해석하고 캐시/원본을 덮어쓰지 않는다. 원본의 날짜·채널 값을 보존한다.
- 페이지·API 모두 ADMIN 전용. 비로그인 401, 본사/대리점 403, 응답 no-store. 요청의 actor 대신 인증 세션 사용자 사용.
- 품목·카테고리·채널 상세 필터, 업로드/계산 시각, 기준월, 미분류/미확정 경고, 판매 원본 ID/행·매입가 근거 제공. 필터는 상세 표에만 적용하며 상단은 월 전체 지표다.

## 시험

- Python 45건 통과: 기존 26 + 지표/원가/재고/이력 19건. 미래·당일 매입 소급 금지, 최신일 단가 충돌, 반품 미확정, 세전 대칭 반올림, 채널 배부 합계, 판매가 재고평가/과거 일자/미평가, 날짜·월 불명확, 원본 재해석, stale 배부, 복수 원본 차단 포함.
- TypeScript 및 Next.js production build 통과. 추가 경고 없음.
- HTTP 34항목 통과: 기존 검토/배부 24항목 + 대시보드 인증/역할/잘못된 월/캐시 차단/미확정 표시/판매·매입·재고 업로드→검토→배부→5개 지표 조회 10항목. 합성 사용자·별도 임시 DB만 사용하며 회사 환경 시험을 대체하지 않는다. 빌드 산출물 초기화 후 재빌드하여 서버 시작과 HTTP 시험을 완료했다.
- Chromium 설치 다운로드가 손상된 압축 파일로 실패하여 브라우저 시각/조작 시험 미실행. 선택 월 전환·필터·모바일 가로 넘침·오류시 이전 월 표시 제거 시험 코드는 준비했지만 PASS로 기록하지 않는다.
- 실거래 원본 대사·회사 PC 배포·실제 관리자/권한·운영 볼륨·ERP API 인증·예약/복구·독립 검토·OWNER 최종 인수 미실행.

```bash
python3 -m unittest discover -s scripts/erp -v
npm run typecheck
npm run build
node scripts/erp/test-http.mjs
# Chromium이 준비된 시험 환경에서만 실행
ERP_UI_TEST=1 node scripts/erp/test-http.mjs
```

## 다음 수용 조건

1. 원본 판매·매입 날짜 형식, 채널 열, 월 전체 수록 범위와 재고 기준일을 실제 자료로 대사한다. 현재 업로드된 엑셀을 재활용하며 미확정은 유지한다.
2. 브라우저 시험 환경에서 준비된 조작 시험과 화면 확인을 완료한다.
3. 코드 검토 후 회사 PC 신규 기능 설치·실계정/비공개 볼륨·백업 복원·예약/중단 복구를 검증한다. 설치 전 기존 코드/ERP 볼륨 백업, 원본 해시·활성자료·검토 이력 대조가 필요하며 `docker compose down -v`를 실행하지 않는다.
4. 준비가 끝난 증거로 KR2~6 수용 및 OWNER 최종 인수를 판단한다. 화면/API 통합만으로 목표 전체를 완료 처리하지 않는다.
