# WP2 업로드·검토 운영 안내

## 2026-11-05 변경

비용 결산 `expenses`와 법인카드 `cards`를 추가했다. 원본은 20MiB, 요청 21MiB, 결산만 압축 해제 200MiB 한도다. 결산은 지정된 48행/4열 요약 범위만 읽고 내부월·배치 라벨을 대사한다. 카드의 반복 제목/소계는 제외하며 카드별·전체 결제원금 합계와 대사한다. 동일 비용/카드 파일은 월 라벨을 바꿔도 중복 활성화하지 않는다. 아래 종전 10MB·비용 미지원 설명은 대체된다.

`/api/erp/reviews` 및 기존 관리자 화면에 원본 행별 검토, 변경 이력, 월 배부 미리보기를 연결했다. 검토자 신원은 인증 세션에서 결정하며 클라이언트의 actor는 무시한다. 처리 상태·귀속월·비용분류·공제/세액·상세/취소/중복 대사 근거를 기록한다. 원본 수정·검토 수정 시 이전 배부를 재계산 필요로 표시하고 삭제하지 않는다.

배부 계산은 실제 판매행 일자와 월 일치를 확인하며 동일월 판매 원본은 1개만 허용한다. 구버전 판매 배치는 보존된 원본을 다시 읽어 거래일을 검사한다. 전체 미검토 비용, 원본 교체, 검토 동시수정, 잘못된 월, 잘못된 카테고리 및 음수/0분모에서 차단한다. 비용이 없으면 0원으로 가정하지 않는다. 검토 후 실제 배부합계 0원은 명시적 확인이 있어야 한다.

모든 결과는 **비용 배부 미리보기**이며 확정 손익 게시 경로는 없다. 요약 결산은 구조 검사만 통과한 것이며 상세 비용 대사가 자동 완료되지 않는다. 승인번호 없는 중복 후보는 보존하고 사람이 근거를 입력해야 한다. 할부·수수료·잔액·포인트 포함 카드는 분리 검토가 필요하여 포함을 차단한다. 자동 비용 분류, 5개 지표 통합, 원가/재고평가, ERP 자동 취득은 별도 잔여 작업이다.

## 구현

관리자 전용 `/admin/erp-imports`와 `/api/erp/imports`. ADMIN만 목록/업로드 허용, POST는 NEXTAUTH_URL과 정확히 같은 Origin 필요. 로그인 세션 정책은 기존 NextAuth를 따른다. 원본 XLSX·SHA256·행별 오류·작성자·시각·수정 전 배치를 SQLite 단일 트랜잭션에 보존한다. 정상 검토자료 전환 실패 시 원본 기록까지 롤백한다. 오류 파일은 격리 보존하고 이전 정상 자료를 유지한다.

중복 기준: 자료종류+기준월+명시적 시트명+파일 SHA256. 수정은 현재 배치 ID가 일치해야 한다(409 충돌 시 새로 조회). 같은 원본 재업로드는 기존 배치 ID 반환, 과거 버전 재입력으로 현재 버전을 되돌리지 않음. 원본 바이트 삭제·수정 API는 제공하지 않는다.

## 저장·실행

Dockerfile에 Python 가상환경과 openpyxl 3.1.5를 포함했다. Compose에 비공개 전용 `erp-private-data:/app/erp-private` 볼륨을 추가했다. 기존 PostgreSQL 스키마 변경 없음. 이는 **아직 빌드/설치된 운영환경을 뜻하지 않는다**.

로컬 개발에서는 `ERP_IMPORT_DIR`을 절대경로로 지정하고 Python에 `scripts/erp/requirements.txt` 설치. 보관경로는 public/uploads 아래를 금지한다. 단일 호스트 로컬 디스크를 사용하며 네트워크 파일시스템·여러 호스트 동시운영은 미지원. 배포 시 볼륨 권한·용량·백업을 확인한다. SQLite 원본 포함 저장은 초기 검토용이며 대용량 운영 DB 이관은 후속 범위다.

## 검증과 복구

- `python3 -m unittest discover -s scripts/erp -p 'test_*.py' -v`
- `npm run typecheck`
- HTTP 회귀: `node scripts/erp/test-http.mjs` (로컬 테스트 전용 서버를 자동 실행, 합성 세션/데이터만 사용)
- 배포 전에 관리자/본사/대리점 계정으로 화면·목록·업로드 권한, 기존 로그인 정책을 실제 환경에서 확인한다.
- 백업은 앱 중지 상태에서 볼륨 복사 또는 SQLite backup API를 사용. 실행 중 단순 파일 복사 금지. 복원 후 원본 SHA·활성배치·수정 이력 대사.
- 되돌리기는 앱 이전 버전으로 복귀, 전용 볼륨 보존. `docker compose down -v` 금지. 현재 세션에서는 운영 배포·재시작·DB 변경하지 않는다.

## 수용 범위와 한계

검증 통과는 **수집 검토 상태**이며 회계 집계·대시보드 확정 게시가 아니다. 기간은 사용자 지정 검토 라벨이며 내부 거래일과 자동 대사하지 않는다. 여러 기간이 겹치는 매입 파일은 합산하지 않는다. 수정 파일은 동일 시트명/범위를 유지해야 한다. 중복 행 검출·전표 정규화·기간 대사는 WP3 연결 전 추가 필요. 재고 파일의 각 시트는 개별 업로드하며 파일 간 재고차이는 기존 CLI 대사로 별도 확인한다. 비용 파일은 이 업로드 스키마에 아직 포함하지 않는다.

10MB 원본, 압축 해제 50MB, ZIP 항목 2,000개, 시트 100,000행/100열, worker 30초 제한. 원본 다운로드 API는 아직 없고 관리자 백업/감사 경로에서 바이트를 보존한다. 최근 100건만 UI에 표시하나 전체 이력은 DB에 보존한다.
